# 03 — Configuração entre sistemas

Copie os `.env.example` para `.env` em cada diretório. `.env` está ignorado pelo Git. Um **rebuild** recompila HTML/JS estático; um **restart** reinicia a API ou painel. Use sempre valores distintos para Sandbox e produção.

`SANITY_API_WRITE_TOKEN` é um segredo temporário somente para a migração editorial, sem relação com Asaas. Os campos `PUBLIC_*` e `VITE_*` entram no HTML/JS público: nunca ponha chave ou token neles. O backend aceita só IDs distintos para filiação e doação e persiste a classificação em `ResourceOrigin`; ao trocar um link, preserve o registro do ID antigo para conciliar cobranças anteriores. Não reclassifique um ID já usado. O ID externo da assinatura é registrado quando a primeira cobrança permite vínculo; os ciclos seguintes usam `subscription`.

O site aceita só URLs `https` em `asaas.com`, `www.asaas.com` ou `sandbox.asaas.com`, sem credenciais embutidas. Um valor inválido ou ausente mantém o CTA indisponível. URLs de retorno opcionais ao configurar o link: `https://site.exemplo.org/pagamento/retorno/` e `/pagamento/cancelado/`. O retorno não prova recebimento.

O painel e a API em origens diferentes precisam de **CORS** (autorização do navegador para uma origem exata), cookie `HttpOnly` e header `X-CSRF-Token` nas mutações. `FRONTEND_ORIGIN` deve corresponder exatamente à URL do painel. Para domínios de sites diferentes, use `COOKIE_SAME_SITE=none` e `COOKIE_SECURE=true`, sempre com HTTPS. Em subdomínios do mesmo site, `lax` pode funcionar. O backend não deve ser aberto com origem curinga. O webhook Asaas não usa cookie nem CORS.
